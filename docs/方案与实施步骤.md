# 外星仔加速器 · 模拟器端自动签到

> 在 MuMu 模拟器里跑一个 UI 自动化脚本，每天自动把「看广告领时长」的三档额度刷满。
> 本文写原理与实现细节；入口和快速开始见根目录 `README.md`。

---

## 一、核心原理

**发奖判定发生在宿主 App 里。**

只要广告 Activity 存活够时间，把宿主主界面拉回前台就自动发奖：

```
点「看广告 领时长」 → 等广告 Activity 起来 → 原地停 15 秒 → 拉回主界面 → 校验时长
```

整个过程只有三步：等广告 Activity 起来、原地停 15 秒、把主界面拉回前台。15 秒就够
（脚本给 15 s + 0~4 s 随机抖动）—— 脚本全程只判断时间和界面状态。

### 对广告联盟的适应性

实测遇到三个联盟，UI 完全不一样，同一套逻辑全部通过：

| 联盟 | Activity | 领奖按钮文案 |
|---|---|---|
| 快手 KSAdSDK | `WMPortraitActivity` | 我要直接拿奖励 |
| 倍孜 BeiZi | `BeiZiNewRewardVideoActivity` | 观看21秒广告领取奖励 |
| 穿山甲 bytedance | `PortraitTransparentAdActivity` | （全屏视频，无按钮） |

脚本只关心「广告 Activity 起来了没有」和「停了多久」，不关心广告长什么样，
所以联盟怎么换都不受影响。

### 停留够时长才发奖

发奖条件是停留满 15 秒。停留不足就回主界面时，进度不变（主界面显示「广告加载失败，点击重试」）。

## 二、发奖链路

发奖由服务端按广告播放记录校验，客户端伪造过不了。脚本走的是「真人看广告」的正常链路：
UI 自动化 + 停留计时。

**一个反直觉的实测结果**：存在「UI 提示领取失败、但时长确实增加」的情况。
所以校验一律以后端接口为准。

### 接口用于读取进度

`/v2/account/pc/ad/config` 会按用户返回每档的 `watchCnt`（今日已完成次数），
而该档的条目个数就是总次数 —— App 自己算界面上那个 `N/M` 用的正是这两个字段
（APK 里 `PcAdConfigLevelItem` 被 R8 保留下来的 getter 恰好只剩
`getWatchCnt()` / `getListList()`）。

所以脚本的判定全部吃这份数据：

| 判什么 | 数据来源 |
|---|---|
| 单轮成没成 | `watchCnt` 增加（可暂停时长净增作旁证） |
| 今天完没完 | 三档 `watchCnt` 都 ≥ 该档条目数 |

比读界面稳：界面会滚动、会漏渲染。接口读不到时脚本不做任何推断，直接停。

## 三、额度体系

| 档位 | 次数 | 单次收益 | 数据来源 |
|---|---|---|---|
| 阶段一 | 9 次 | 20 分钟 | `pc/ad/config` 条目数 × 奖励秒数 |
| 阶段二 | 3 次 | 30 分钟 | 同上（带「1.5倍增幅」标签） |
| 加油包 | 9 次 | 10 分钟 | 同上 |

单日满额 21 轮，换到 `9×20 + 3×30 + 9×10 = 360 分钟`（6 小时）可暂停时长，
耗时约 20 分钟（含每轮 6~14 秒随机间隔）。

### 实测时间线

```
起步                     2 时 0 分
├ 阶段一 9 次 × 20 分    → 3 时 0 分
├ 阶段二 3 次 × 30 分    → 4 时 30 分
└ 加油包 9 次 × 10 分    → 6 时 0 分
```

三档全满后主按钮变成「今日广告已看完，请明日再来」。脚本只看接口的 `watchCnt`，不看文案 ——
单档耗尽时界面也会冒「今日次数已用完」，文案容易误命中。

## 四、环境依赖

| 项 | 值 |
|---|---|
| 模拟器 | MuMu 12，装非系统盘；给 4 GB 内存、4 核 |
| adb | 模拟器自带，路径填进 `config.json` 的 `adb_path` |
| 设备 | MuMu 新版 `127.0.0.1:16384`，老版 `127.0.0.1:7555` |
| Python | 3.8+，依赖见根目录 `requirements.txt` |

凡是因机器而异的值（模拟器路径、adb 路径、实例编号、OAID、设备端口）统一放
`config.json`（已被 `.gitignore` 忽略），代码里只读不写死；缺了就报错并指出缺哪一项。

### OAID 这一关

广告 SDK 要靠 OAID 才请求得到广告。MuMu 默认伪装成 Xiaomi，没有配套的 OAID 服务，
所以脚本给它注入一个：把品牌属性改成 OnePlus（OPPO 系），广告 SDK 就会走 OPPO 路径
去读 `persist.oaid`。

脚本里的 `ensure_ready()` 每次自动做这件事（幂等）：

```bash
setprop persist.oaid <config.json 里填的 UUID>
/data/adb/ksud resetprop ro.product.manufacturer OnePlus   # 其余 7 个 ro.product.* 同理
```

`ro.*` 是运行时覆盖，**MuMu 每次重启都会还原**，所以每次运行前都要重刷；
`persist.oaid` 是持久属性，重启保留。

## 五、开机自动执行

每次登录 Windows 触发一次，同一天只跑一次。完整流程：

```
登录 Windows
  └ 等 30 秒（让开机先稳定）
  └ 今天跑过没？→ 跑过就退出
  └ 确保 MuMu 主程序在跑（不在就拉起）
  └ MuMuManager 拉起模拟器
  └ 等 adb 就绪 → adb root（拿 uid=0）→ 注入 OAID + 品牌属性
  └ 拉起外星仔 → 循环刷满三档额度（约 20 分钟）
  └ 记录状态 → 完全关闭 MuMu（实例 + 主程序）
```

### 触发方式：注册表 Run 键

```
HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run\EtalienDailyCheckin
  = "<python 目录>\pythonw.exe" "<项目目录>\scripts\checkin.py" --delay 30
```

`pythonw.exe` 无窗口、不弹黑框；`--delay 30` 是登录后再等 30 秒，避开开机高峰。

```bash
$PY scripts/checkin.py --install     # 写入 Run 键
$PY scripts/checkin.py --uninstall   # 移除
```

选择 Run 键的理由：**零权限**、**登录即触发**、**不经过 shell**，直接调 `pythonw.exe`，
任务管理器「启动」标签里能看到、能禁用。

### 每日去重

状态在 `output/state.json`，字段含义与判定规则见 `README.md`。这里只记两个容易踩的点：

- `save_state()` 是 merge 语义。**跨天时若发现 `date` 变了，立即丢弃全部旧字段**，
  这样昨天的 `all_done=true` 不会漏进今天。
- 额度只在 0 点整重置，**只看日期、不看时间段**（实测 `00:18` 起始读到 `阶段一 0/9`，
  当天 `02:31` 刷满 `9/9  3/3  9/9`）。所以任何时刻看到三档全满，都是当天真的刷满了，
  直接认可。

```bash
$PY scripts/checkin.py --state       # 看当前状态（不连模拟器）
```

## 六、排查速查

| 现象 | 处理 |
|---|---|
| `oaid sdk not find` / `无广告填充 1010` | 见第四节，刷品牌属性 + `persist.oaid` |
| `ksud` 报 Permission denied | 需要 uid=0。`ensure_root()` 先 `adb root`（回 `restarting adbd as root`），再 `wait-for-device` + 轮询 `id`，确认 uid=0 才继续 —— adbd 重启期间命令仍是 `shell(uid=2000)` |
| 注入属性的命令迟迟不返回 | 走 `adb shell`，不要用 `MuMuManager.exe sh`：后者超时后杀不掉子进程，会把调用它的 Python 一起拖住 |
| 冷启动后品牌属性刷不进去 | `is_android_started` 早于系统就绪，命令会返回空。靠重试兜住（8 次） |
| MuMu 重启后变横屏（1920x1080） | `MuMuManager.exe setting -v 0 -k resolution_mode -val phone.1` 固定竖屏 |
| 主按钮 `UIADSubmitText` 找不到 | 竖屏分辨率下页面过长、按钮被挤出滚动区，`ensure_on_ads_page()` 会上滑 4 次 |
| 满额后进度读不到 | 界面文案会变「已完成」/ 滚动出屏，判定读接口（`watchCnt`）而非文案 |
| 广告页回不到主界面 | `am start -n <宿主 MainActivity>` 万能穿透（`punch_home()`） |
| 返回键按多了弹「确定要退出吗」 | `dismiss_popups()` 里已处理 |
| Git Bash 把 `/sdcard/xxx` 转成 Windows 路径 | 命令前加 `MSYS_NO_PATHCONV=1` |
| adb 写中文路径失败 | 用 `adb exec-out screencap -p > 文件`，重定向交给 bash |
| 中文输出乱码 | 设 `PYTHONIOENCODING=utf-8` |

## 七、风险

自动化可能违反服务条款，存在被风控的可能。用自己账号，后果自负。

本方案做的是「在安卓环境里正常观看广告」，属于正常链路；伪造广告回调属于欺诈广告主，
不在本项目范围内。
